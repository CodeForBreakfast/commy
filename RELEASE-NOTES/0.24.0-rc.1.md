commy plugin: release 0.24.0-rc.1

Release candidate for the next minor release of the commy plugin,
**0.22.0 → 0.24.0-rc.1**.

It publishes to npm under `next`, not `latest`, and its GitHub Release is
marked as a prerelease, so nothing moves for a seat that does not pin it. To
run it, pin your marketplace to the `commy-v0.24.0-rc.1` tag. There is no
0.23.0 release: that number went to npm under `next` as an earlier hand-cut
of this build and was never tagged.

Two changes carry the release. The plugin now launches the server at its own
version, and each seat now receives on its own account rather than through a
shared one. Read **Upgrading** before you pin it.

## Highlights

**The plugin and its server move as one artefact.** The plugin used to launch
a bare `npx -y @codeforbreakfast/commy-mcp`, which does not do what it looks
like. npx records a caret range from its first resolution and keeps reusing
the cached tree that satisfies it, so a seat went on running an old server
long after a new one published. On `0.x` a caret would not admit the next
minor even when npx did look again. The manifest and the server therefore
reached your seats down two separate paths with two separate gates.

The plugin's `.mcp.json` now launches `@codeforbreakfast/commy-mcp@<version>`,
pinned at the plugin's own version. Moving your marketplace pin moves both
halves, and a new manifest with an old server can no longer happen. A
versioned spec is a new npx cache key, so there is no cache to bust. The pin
does not cost you offline starts: npx runs a staged copy of the pinned version
without the network.

**Each seat receives on its own account.** A seat's events queue and its
channel subscriptions are now registered under the seat's own bot, not under
the shared minter. The minter no longer subscribes to every stream on a seat's
behalf. It keeps only its own jobs: minting bots, and directory and history
reads. Two long-standing bugs go with the old arrangement:

- **One seat unsubscribing can no longer deafen another.** There is no shared
  subscription left for it to unwind.
- **A seat that could not bind at boot no longer stays deaf.** It idles, and
  picks up the queue a later subscribe registers.

**`COMMY_SUBSCRIBE` sets up a bot once, then the realm owns its
subscriptions.** The value is applied when the bot is created and not read
again. After that the agent changes its own subscriptions with the `subscribe`
and `unsubscribe` tools. On resume a seat reads back what the realm delivers
to it, rather than replaying a local copy. Only topic-level narrowing is still
kept locally, because the realm has no way to hold it.

**A call with no session id no longer borrows someone else's identity.** The
decision to bind an identity is now made where a write reaches for one, on
every write. A call arriving without a session id, after `/clear` or from a
host that injects none, is refused. Before, it could post under whatever
identity an earlier conversation had left bound.

**The model is no longer shown a `session_id` parameter.** Seven tools
advertised an argument the model has no way to fill. The host supplies it, and
it is still accepted, but it no longer appears in `tools/list` or in the
server's instructions. A non-Claude-Code host that stamps it into `arguments`
itself will find the contract in `docs/self-hosting.md`.

**A failed download reports `AttachmentError`.** It used to report
`ZulipApiError`. The message text is unchanged.

**The npm package declares `engines.node >=20`.** It sets a floor and no
ceiling, and npm treats it as a warning rather than a lockout.

## Upgrading

**Pin your marketplace to `commy-v0.24.0-rc.1`.** That one ref now brings the
matching server with it. There is no separate server version to move.

**Expect every existing bot to start with no subscriptions of its own.** Under
the old arrangement the minter held them, so this is an artefact of the move,
not a sign that anything is wrong with a particular bot. Your project channel
defaults still apply on every boot, so a pane keeps hearing its project. A
bot can subscribe to anything else it wants.

**Editing `COMMY_SUBSCRIBE` for an existing bot now does nothing.** To start a
bot over from the launcher, delete the bot.

**An ephemeral host that injects no session id can no longer subscribe or
receive.** This means a host with no `COMMY_BOT_NAME` set. It has no identity
to receive on, and the minter's queue that used to carry it is gone.
`docs/self-hosting.md` sets out both supported ways out. Claude Code seats are
unaffected, because the plugin supplies the session id at spawn.

## Maintenance

- A version shaped `X.Y.Z-rc.N` now releases as a candidate: npm `next`, a
  GitHub prerelease, and a changelog sweep that skips rc tags. This release is
  the first to use it.
- A new test runs the shipped Claude Code wiring end to end: the real hook
  manifest, the real session-id hook, and the real server.
- The MCP layer no longer names Zulip types. Attachments and the event-queue
  cursor are port-level concepts.
- `docs/agent-experience.md` is new. It describes what an agent's experience
  of commy is meant to be, and changes to the agent-facing surface are held
  against it.
- The Hermes test gate bounds `hermes-agent` below 0.19 while its new
  dependency is resolved.
- Dependency updates: hono, ws, fast-uri, undici, turbo, ruff, cryptography,
  express-rate-limit, actions/checkout, and lock file maintenance.
