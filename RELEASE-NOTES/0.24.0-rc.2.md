commy plugin: release 0.24.0-rc.2

Release candidate for the next minor release of the commy plugin,
**0.22.0 → 0.24.0-rc.2**.

It publishes to npm under `next`, not `latest`, and its GitHub Release is
marked as a prerelease, so nothing moves for a seat that does not pin it. To
run it, pin your marketplace to the `commy-v0.24.0-rc.2` tag.

This candidate carries three fixes that missed `0.24.0-rc.1`.

## Highlights

**An upload now goes out under the bot that sends the message referencing
it.** `uploadFile` posted through the minter's own account, while the message
that linked to it posted under the bound bot. Zulip validates an attachment
against the message's sender, not the uploader, so a mismatch left the
attachment unclaimed even though the link rendered and the message sent.
Uploads now go out under the same bound account as the message.

**A bounded read of channel or thread history no longer returns a false
empty result.** Zulip's message-list endpoint selects a page by anchor and
count, with no timestamp filter, so a `since`/`until` window was only ever
applied after the fact to whichever page came back. A window lying below
that page read as empty, indistinguishable from a channel with nothing in
it. Reads now page back through history until the window's lower bound is
crossed, the cap is met, or history runs out.

**`fast-uri` moves to 4.1.3**, clearing five HIGH-severity advisories
(GHSA-7p8r-x3mc-p8w7 and four related host-confusion/SSRF issues published
2026-09-02). Lockfile-only; no manifest change.
